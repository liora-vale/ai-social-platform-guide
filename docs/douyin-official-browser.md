# 让 AI 浏览抖音：官端内置浏览器方案

## 一、结论

这套方案不需要购买 VPS，也不需要部署 `douyin-mcp`。

实际使用的是 AI 产品自带的浏览器或电脑操作能力。用户在该浏览器中亲自登录一次，AI 随后可以在同一浏览器会话中浏览推荐、搜索视频、打开详情、阅读评论和查看公开主页。

## 二、使用前提

AI 必须真正具备以下能力之一：

- Browser / 浏览器工具；
- Computer Use / 电脑操作；
- Remote Browser / 云浏览器；
- 其他能够点击、输入、滚动并读取网页内容的工具。

普通联网搜索不等于浏览器操作。只能返回公开搜索结果的 AI，无法仅凭提示词登录抖音。

## 三、登录步骤

先把下面这段话交给 AI：

> 请使用你能够操作的内置浏览器打开抖音网页版。暂时不要点赞、评论、关注、收藏、转发或发布，只停留在登录页面。需要扫码、密码、短信或其他身份验证时暂停，让我本人接管完成。不要要求我在聊天中提供、回显或导出密码、验证码、Cookie 或 Token。

登录完成后再说：

> 请检查是否已经正常登录。只读取页面显示的账号头像、已登录导航和首页内容，不进行任何互动。

## 四、只读验收

第一次测试建议使用：

> 请在抖音搜索“自媒体运营”，打开三条正常相关视频，分别整理标题、作者、主要观点和可见高赞评论。遇到直播、广告或无关内容直接跳过。不要点赞、评论或关注。

验收至少包括：

1. 搜索结果能够出现；
2. 能打开视频详情；
3. 能读取作者、文案或页面可见信息；
4. 能展开并读取评论；
5. 返回搜索页后不会丢失登录状态。

## 五、开放互动能力

建议按影响从低到高逐步开放：

| 操作 | 推荐规则 |
|---|---|
| 搜索、阅读、总结 | 可直接执行 |
| 点赞、收藏 | 首次执行前确认；之后可由用户决定是否长期授权 |
| 关注、评论、转发 | 先展示目标和内容，得到明确确认后执行 |
| 私信、发布、删除 | 每次确认具体对象与最终内容 |

评论示例：

> 找到适合互动的视频后，先告诉我作者、目标视频和拟回复文字。没有得到我的确认前不要发送。发送后重新打开原视频确认评论是否出现；如果结果不明确，不要重复发送。

## 六、登录状态

登录信息通常保存在该浏览器的隔离会话中。是否能跨对话、跨设备或长期保留，取决于具体 AI 产品。

以下情况可能要求重新登录：

- 浏览器会话被清空；
- Cookie 到期；
- 平台要求重新验证；
- 网络或设备环境显著变化；
- 账号触发保护机制。

不要手动把 Cookie 发给 AI。浏览器可以在自己的隔离环境中正常维护会话；凭证不应进入聊天、截图或公开仓库。

## 七、不应进行的操作

- 批量关注、批量点赞或群发相同评论；
- 绕过滑块、验证码或平台风控；
- 高频重复刷新或连续提交；
- 将账号凭证、Cookie 或二维码截图上传 GitHub；
- 在不确定是否成功时重复发送评论。

## 八、没有内置浏览器怎么办

这时才考虑：

`AI → MCP 服务 → 本地或 VPS 浏览器 → 抖音`

自建方案通常还需要处理可见登录、Cookie 安全、无头浏览器验证、页面更新和长期维护。它不是本章的默认路线。
